0023 - Therefore this is a schema-side capability retreat, not a validator waiver: a provider may
0024   now emit duplicate refs and the consumer will still fail them.

0026 ## Amend item A1 - owned child not cleaned up on the new fail-closed path
0027 
0028 - V7 root PS 0031-0033 captures the child CIM identity and birth before the key write at
0029   0036, and uses the same CIM birth for the inner watchdog (0040) and the outer readback
0030   (0034 start.json). Exact string equality is kept; no time window or coarser match.
0031 - Defect line: 0032 throws when the CIM identity is null or mismatched, so 0033 never sets
0032   `$birth`; 0061 then requires `$null -ne $birth` before killing and 0065 only disposes.
0033 - Trigger: `Get-CimInstance` returns `$null`, throws, or cannot resolve `ExecutablePath`
0034   immediately after `Start()` - provider visibility race or provider error, the exact
0035   failure path the new hunk introduces.
0036 - Effect: the owned Node child is not killed by the driver and its exit is not reaped; only
0037   stdin EOF after disposal/exit ends it. The key has not been written yet on this path, so
0038   no credential exposure, but the "owned child is always cleaned up" property fails here.
0039 - Same root cause on the watchdog path: the kill at 0040 needs a second successful CIM
0040   re-query. If the provider keeps failing, 0041 throws and 0063 skips the kill although the
0041   key was already delivered at 0036, so a live consumer can outrun the declared failure.
0042 - Minimal fix: in `finally`, when `$null -ne $child -and -not $child.HasExited`, call
0043   `$child.Kill()` followed by `$child.WaitForExit(5000)` independently of `$birth`. The
0044   Process handle is authoritative and cannot hit a reused PID; keep the CIM exe+birth
0045   equality checks for PID-based cross-process readback, and optionally bound-retry the 0031
0046   capture briefly before throwing.
