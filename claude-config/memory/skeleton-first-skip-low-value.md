先搭框架、先把能看到的样子做出来；不要在意义不大的事上耗时间。

**Why:** 2026-10-02 T21 重试跑里，我按执行令字面意思把开发机 AppData（89 万文件、116 GB）全扫了 2 小时 21 分，用户问"为什么要扫那么多文件""扫描这个干嘛，肯定是停"，随后说"没必要做这种意义不大的事，先搭框架，先把样子做出来"。开发机没装客户端，那次扫描本身证明不了什么。

**How to apply:** 执行令里耗时长、在当前环境下结论没意义的步骤（全盘扫描、长时间压测、等待外部前提的验证），先估耗时和价值；明显不值的，先做有产出的部分，把这一步写成"建议跳过/改到验收机"交主编排，或开工前一句话问用户，而不是闷头跑完。用户在场时长任务开跑前先说预计多久。

2026-10-03 用户再次明确"以提交为主，尽量少做无意义的事"（ORCH 广播 1712 定为全线口径）：做完要求的、有一次红绿、写了交付说明就交回；工作线不自己跑全量（全量由主编排合流时统一跑）；每条要求一条证据，不为同一不变量堆多种变异；卡住超 30 分钟就落回执、换别的或候令。相关：[[owner-relays-when-present]]
