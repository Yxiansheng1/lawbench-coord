## 2. `.doc` 外链图片：裁决为"查到就拒绝转换"

你给的三个选项都不采用，理由：

- ① 记为残余风险：所外访问时律师的电脑是连着公网的，请求真能发出去。不能接受。
- ② 先转一遍再删外链：第一遍转换本身就会取图。
- ③ 系统防火墙拦 soffice：改系统设置，而且律师电脑上别的地方装的 LibreOffice 也会受影响。

**采用的做法**（已写进 `main` 的 Spec 14.3）：把 `.doc`、`.wps` 交给 LibreOffice 之前，先检查文件里有没有指向外部地址的图片链接，有就拒绝转换。

| 项 | 要求 |
|---|---|
| 检查什么 | 旧版 Word 二进制文件里的图片链接域（`INCLUDEPICTURE`）和链接对象，目标以 `http://`、`https://`、`\\`（UNC）开头的。文件里的文字是 UTF-16LE 或单字节编码，两种都要查 |
| 查到之后 | 不调用 LibreOffice。返回中文原因："文档里有指向外部地址的图片，为避免联网没有转换；请在 Word 或 WPS 里断开链接（或另存为 docx）后再试" |
| 拿不准的时候 | 宁可误拒。文档正文里普通的网址文字（超链接）不应触发拒绝；如果分不清是图片链接还是普通超链接，先按拒绝处理，把误拒的情形写进交付说明 |
| 测试 | 把 xfail 的 `test_doc_with_external_image_does_not_fetch` 改成：带外链图片的 `.doc` 被拒绝、监听收到 0 次请求、原文件哈希不变；再加一个正例：不带外链、正文里有一个普通网址文字的 `.doc` 能正常转换 |
| `.xls` | 你已经设了 Calc 链接不更新。请补一个同样用本机监听的测试确认 `.xls` 里的外部链接不会发请求；如果也拦不住，同样按"查到就拒绝"处理并落注记件 |

## 3. T21 续跑缺陷（主编排亲核时发现）

我在临时目录里实测了 `2b23357` 的 `find_leaks.py`：

| 步骤 | 结果 |
|---|---|
| 第一次全扫，目录外有两处副本 | 不通过，命中 2 处 ✔ |
| 同参数再跑 | 结论不变 ✔ |
| 去掉副本后 `--fresh` | 通过 ✔ |
| **在 `d1` 里新放一个副本，不带 `--fresh` 再跑** | **通过（没有命中）✘** |

原因：上一次已经全部扫完，进度文件还在，下一次运行把每一批都当成"已扫过"直接沿用旧结果。后果：验收时如果前一天跑过一遍，第二天不带 `--fresh` 再跑，会拿前一天的结果报"通过"，当天新出现的泄露查不出来。这正好是这个脚本要防的事。

要求：

| 项 | 要求 |
|---|---|
| 续跑只对"没跑完的那一次"有效 | 一次运行把所有批次都扫完后，进度标记为"已完成"；下一次运行自动从头开始，不需要 `--fresh` |
| 证据里写明 | 本次运行的开始时刻；哪些批次是本次扫的、哪些是沿用上次中断前的结果（附那次的时刻）；沿用的批次超过 24 小时的，不沿用，重扫 |
| 输出 | 末尾"已搜索 N 个文件"要分开写本次实际扫的和沿用的 |
| 测试或演示 | 把上表第四步做成演示，补进 `resume-demo.txt` |
| 顺带 | 删掉误提交的空文件 `docs\plan\evidence\T21\resume-demo.txt.tmp` |
