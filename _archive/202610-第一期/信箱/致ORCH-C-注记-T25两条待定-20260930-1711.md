# 线C 注记 · T25 开工后两条要主编排定（阻塞"走完一期"验收）

## A. ENGINE_FAILED 失败体装不下引擎输出
- 工单步骤 1："退出码 0 / 2 / 其他分别映射为成功、attention、ENGINE_FAILED"；Spec 回写②"见 [BLOCKED] 判 ENGINE_FAILED"。
- 但 `common.schema.json#/$defs/fail` 只有 `{ok:false, error:{code,message}}`（additionalProperties:false），而 ENGINE_FAILED 的提示是"发票整理未完成，请查看下方的输出信息"——失败时"下方的输出"没有地方放。
- 实测（虚构样本）：prepare 在有待核项时输出 `[BLOCKED] ValueError 收集任务有待处理或数量不符项；先处理或另建明确范围任务`；reimburse 未建批次时 `[BLOCKED] FileNotFoundError …_报销批次\<批次>.json`。律师只看到"发票整理未完成"，看不到原因。
- 选项：① 契约给 invoice_run 的失败另开一种成功体（如 `ok:true, value:{exit_code, attention:false, failed:true, output,…}`）；② common 的 fail 加可选 `detail`（影响全部接口）；③ 维持现状，律师看不到原因。线C 暂按工单做 ③（fail 体），改动集中在 runner.run 的最后三行，定了就改。

## B. invoices-01 走不完一期（验收"plan → run → analyze → reimburse 预览 → --apply"）
- 引擎把 `发票01-办公用品.pdf` 判为"待核：分类缺失或需人工核定"（invoice_integrity.py:41），`发票04`（01 的重复）也随之"待核"。
- 白名单里能处理待核的只有 `review`，但 review 对字段错误直接拒：workflow.py:162 `if buyer_errors(fields) or admission_errors(fields):raise ValueError('字段错误不能通过简单确认放行，需修正识别并重新核验')`。
- 于是 `processing_complete=false`，`prepare --job` 被拒（上面 A 的输出），批次建不起来，reimburse 无从预览。
- 选项：① 按 Spec 20.12 的待定把 `exclude` 并入白名单（参数已在 1701 注记给出：`--job --item --reason --reviewer --confirm`，不联网，只改 collection.json）；② T1 改样本让发票01 能分类（分类表关键词含"办公用品"，样本的商品名大概没命中，待查）；③ 两者都做。线C 倾向 ①+②：真实律师也会遇到分类不出的票，没有出口就卡死。
- 在定之前，test_invoice 先测到 analyze（重复、抬头不符在输出明细中、退出码 2），并测 prepare 在有待核项时判 ENGINE_FAILED；"走完一期"那条标 xfail 并写明原因。
