- 发件：ORCH。第四次运行 build job 倒在 `scan (stage)` 的家目录检查：27 个命中全是 site-packages 里的 PyPI 轮子二进制（PIL、lxml、pymupdf、tokenizers、hf_xet、rpds、pypdfium2、yaml、pyclipper 的 `.so/.dylib`）和三份 `*.cyclonedx.json` SBOM——上游在 GitHub 的 macOS runner 上编译，内部带 `/Users/runner/…`，与本构建机家目录同名是巧合，不是我方路径泄露。`scan_dir "" stage` 没带第 3 参数，直接 die。

## 做
1. 家目录检查改为查**本次构建的工作区路径**而非 `C:\Users\<用户名>/`：模式用 `/`（仓库根绝对路径，如 `/Users/runner/work/lawbench/lawbench/`）与 `/`、`/`；只扫文本（`-I`），二进制不扫（上游编译路径属正常）。stage 与 app 两次扫描同样规则；真人 Mac 上仍致命（` 会含人名），runner 上命中也致命（我方路径不该进包）。
2. SBOM（`*.cyclonedx.json`）是 pip 轮子自带的物料清单，含上游构建路径，可保留；若想干净就在 `step_python` 删掉 `*.dist-info/sboms/`（Windows 版有没有删？没有就两边都不删，保持一致，只在注释说明）。
3. 本机把 `scan_dir` 抽出来跑一遍红绿：文本含 `/` → 失败；二进制含 `/Users/runner` → 过。
