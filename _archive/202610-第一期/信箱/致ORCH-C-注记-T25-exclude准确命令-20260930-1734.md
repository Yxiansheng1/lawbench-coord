# 线C 注记 · 引擎 exclude 的准确命令（答 1701 令 P4）

- 命令行：`python engines\invoice-ledger\scripts\invoke.py workflow.py exclude --job <发票台账\_任务\<报销年月>> --item <记录ID> --reason <理由> --reviewer <核验人> --confirm`
- 参数：定义 `workflow.py:26`，五个全部必需；**没有 `--apply`**，用 `--confirm` 表示确认——不带 `--confirm`、或 `reason` / `reviewer` 为空白，直接 `[BLOCKED] ValueError 人工排除须明确理由、核验人及confirm`（`:123`），退出 2。
- `--item` 是任务里的记录 ID：64 位小写十六进制，就是 `收集对账表.csv` 第一列"记录ID"（例：`6801d571…0f40`）。ID 不存在时 KeyError → `[BLOCKED]` 退出 2。
- 做什么（`:122–128`）：在任务目录加锁（`_transaction.lock`），把该项状态改为"人工排除"、原因为理由，并记 `manual_exclusion={reason, reviewer, at}`；随后 `reconcile` 重算统计。
- **写哪些文件**：只在任务目录内——`collection.json`（原子写）、`收集对账表.csv`（重写）、`_transaction.lock`。**不碰台账**（主台账、`_原票`、`_提取记录` 都不动），原票文件不删。
- **联网**：不会。代码路径只有 load / 改字典 / reconcile / save；`workflow.py` 模块顶部 import 了 `mail_collect`（含 imaplib、urllib），但只是导入，exclude 分支不调用任何收取或下载函数。与 run / analyze 同一进程模型，T25 的连接取证里 31 个引擎进程 0 条连接。
- 可逆性：没有"取消排除"子命令；要恢复只能重新 plan / run（新建任务）或手改 collection.json。界面应当逐项确认、写明"排除后本期不再计入该票"。
- 契约建议（1.3 内，不升版）：`{action:"exclude", period, item: ^[0-9a-f]{64}$, reason: 1–200 字, reviewer: 1–40 字, confirm: const true}`；服务一律带 `--confirm`（与 cancel 带 --apply 同理，确认在界面做）。
