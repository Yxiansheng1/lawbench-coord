# 注记 · A → ORCH · T7 凭据插件的授权记录（偏离 Q2 裁决，请确认）

- Q2 裁决原文："只认 `LAWFIRM_KEY`……授权记录读取返回空、写入拒绝；不读环境变量"。
- 实测（桌面端对假服务首次启动，2026-09-29 23:09）：启动失败，`dsh: startup failed: 1 required plugin did not activate`。调用栈：`LawbenchCredentials.modifyRecord` ← `initializeSecret` ← `BrowserAuth.create`（`dsh/packages/client/connection/lib/index.js:330,367`）。即 DSH 自己的连接插件在启动时要把浏览器会话密钥写成一条记录（旧的 `.credentials.yaml` 里就是这条 `client-connection/browser-session`）。写入拒绝，桌面端就起不来。
- 线 A 的处理（临时，候你定）：记录只放进程内存——不落盘、不进凭据管理器、不读环境变量，每次启动重新生成；Key 仍然只在凭据管理器（resolve / set 只认 `LAWFIRM_KEY`，不变）。这样 D9"Key 只在凭据管理器"不受影响，`.credentials.yaml` 也不再产生。
- 可选的另一种做法：记录也存凭据管理器（跨重启保留浏览器会话）。线 A 不倾向：多存一类密钥，收益只是重启后不用重新认证（桌面端每次启动本来就重新认证）。
- 测试：`dsh-ext\tests\credentials.spec.ts` 已改为"记录只在内存、新实例读不到、写记录不碰凭据管理器"。
