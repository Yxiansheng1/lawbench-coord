# 线 A 注记 · T17 活着的句柄：冻结清单两处修法在 DSH 上做不到，按同一目标改道（2026-10-01 17:20）

执行令 1711 第 F1-①、F1-② 两条的**机制**都不成立，读源码与实测如下（目标不变：活着的会话复制/搬家后续写落新文件夹；落不了就明说、不写旧处、不静默丢）：

1. **F1-① 路由代理拦写方法不起作用**：活着的会话写记录**不经句柄的 `append`**。原版 JSONL 实例在 `install()` 里监听全局 `session/event`，按会话编号投给自己实例里登记的"写入者"（`session-persistence-jsonl/src/storage.ts:535–554`，`enqueueLive` → 定时批量落盘）。我在路由代理上拦了 `append`，用复核员 B 的真 AgentLoop 实验跑：代理确实包上了写句柄，但整轮一次 `append` 都没被调到，结果与修前相同（复制写进旧处、搬家丢失）。
2. **F1-② "放下活着的 Agent"没有公开办法**：Agent 只能由创建者凭 `AgentHandle.dispose()` 拆掉（`core/agent/src/index.ts:146–163`）；会话控制器 resume 后直接丢掉 handle（`session-controller/src/agent.ts:437/469` 的 `(await ctx.agents.resume(...)).agent`），归档的 `workspace/session-stop` 也只是取消当前一轮、不拆 Agent。要拆只能动 agent-loop 的私有生命周期，风险太大，不做。

**改道（全在我方代码，不改 DSH）**：
- **搬"写入者"而不是拦写方法**：名单刷新后（`caseOpen` 之后那次、挂回前那次），对路由手上每个"所属案件根已不在名单上或已不在盘上"的写句柄：若该会话的 Agent 正在跑，等它空闲；然后关掉旧句柄（原版 close 会把缓冲的事件落进旧文件、注销旧实例里的写入者），核对新位置这条记录与旧处事件数一致，再在新位置的实例上以写方式打开——此后 `session/event` 按编号投到新实例，续写落新文件夹，旧文件夹不再变。
- **搬不了就拒绝这一轮**：新位置找不到、或事件数对不上（复制之后旧处又写过）时，不重新登记写入者；我方 Agent 插件在下一轮开始（`agent/pre-step`，T13 的 INPUT_CHANGED 同一机制）发现该会话"写入位置已失效"就整轮拒绝，输入区显示中文说明"这个对话所在的案件文件夹已经不在原来的位置…请从首页重新打开案件"。不写旧处、不静默丢。
- 验收仍用复核员 B 的三份 spec（真 AgentLoop，复制与搬家）+ 拒写路径用例。
