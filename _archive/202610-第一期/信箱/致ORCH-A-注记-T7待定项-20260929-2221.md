## Q1 凭据插件没法用"整行替换"装进去 ✔
- 原文：Spec 3.1 表 `credentials` 行"整行替换为我方凭据插件 `lawbench-dsh/credentials`"；工单 T7 步骤 4"补丁中替换 `credentials-local` 行"。
- 问题：DSH 补丁里如果写了 `name`、又和原行的插件名不一样，DSH 只报警告并跳过这条补丁（`dsh/vendor/include/src/index.ts:115-118` "name mismatch … skipping"）。换插件这件事，靠补丁做不到。
- 方案：①把原 `credentials` 行设成 `disabled: true`，另插一行我方凭据插件，提供同名服务 `credentials`；②改 base 组合包源码。倾向①，零源码改动。Spec 3.1 的写法要跟着改。

## Q2 凭据服务接口按多大范围实现 ✔
- 原文：Spec 8.1"实现与 `credentials-local` 相同的服务接口"。
- 问题：
  - 这个接口分两部分。一部分按环境变量名取值（resolve / describe / set / unset）。另一部分按插件存授权记录（readRecord / listRecords / modifyRecord / deleteRecord），`llm-pi-ai` 每次请求都会调用（`dsh/packages/llm/llm-pi-ai/src/auth.ts:147,150`）。Spec 没说第二部分存到哪里。
  - `credentials-local` 的规则是进程环境变量优先。我方照做的话，环境变量 `LAWFIRM_KEY` 会盖过凭据管理器里的 Key。
- 方案：①只认 `LAWFIRM_KEY` 这一个名字，从凭据管理器读；其他名字返回"未配置"；授权记录读取返回空、写入拒绝；不读环境变量。②全部照 local 的做法，记录也存凭据管理器。倾向①，面最小，和 D9"Key 只在凭据管理器"一致。

## Q3 首次配置页怎么连到工作台服务，"没配置过服务器"怎么判断
- 原文：工单 T7 步骤 5"测试连接调 `/api/connection/test`；判断条件改为'没有配置过律所服务器'"。
- 问题：
  - 通路：欢迎窗口在 Electron 主进程里，只能经 Host 的 `/api/<命名空间>/<方法>` 调用（`apps/desktop/src/welcome-backend.ts:47-61`），它不知道服务的端口和令牌。可是 `lawbench` 远程命名空间和 P-6 排在 T13。
  - 判断依据：契约 `files/settings.schema.json` 里四个地址都是必填，没有"已配置"标记。按线 B 分支的实现，settings.json 不存在时服务直接返回默认值，界面分不出"没配过"和"配的就是默认值"。
- 方案：
  - 通路：①T7 在 Host 插件里先做一个最小的 `lawbench` 远程服务，只有 settings、connectionTest 两个方法，T13 再扩充；②另开一条主进程专用的私有通道。倾向①。
  - 判断依据：a 以 settings.json 是否存在为准；b 契约加 `configured` 字段（要升版本）；c 凭据管理器里没有 Key 就算没配置。倾向 a 加 c，不动契约。

## Q6 工具定义：返回结构、失败怎么表示、`$ref` ✔
- 原文：Spec 20.4"`$defs/args` 直接用作 DSH `ToolDefinition.parameters`，`$defs/result` 是…`value` 的结构"。
- 问题：
  - DSH 注册工具时必须带 `output.schema` 和 `render` 函数。`output.schema` 过一道受限校验（`packages/core/tools/src/index.ts:1063-1071` 调 `assertSupportedJsonSchema`），`$ref`、`anyOf`、`pattern` 等写法会被拒，契约里的 `$defs/result` 不能直接用。
  - `/core/tool` 返回 `ok:false` 时，是抛工具错误还是当普通值返回，Spec 没说。
  - `render` 给模型看的格式没定。
  - `case_suggest_wiki` 参数里有 `$ref: lawbench://…`，原样发给模型等于一个解析不了的引用。
- 方案：`output.schema` 用宽松写法（不作约束），结果由我方按契约校验；失败时抛错，把中文 `message` 给模型；`render` 输出 JSON 文本；注册前把 `$ref` 展开。Spec 20.4 补一句。

## Q10 预算怎么计数 ✔
- 原文：Spec 9.2 预算"工具调用 24 次…`case_save_draft` 不计入"；T7 验收"第 25 次被拒绝"。

## 已核对、不用问的点
- 补丁里 `baseURL` 已是 `http://127.0.0.1:18765/v1`。
- Spec 1.2 列的挂载点在固定提交里都存在：`agent/pre-step`、`agent/request`、`tools/pre-execute`、`session/event`；`turn/end` 的结束原因种类也对得上；`exec.agent.id` 就是会话 ID。
- 子进程环境变量：DSH 只清掉名字含 KEY / PASSWORD / SECRET / TOKEN 的变量和 `DSH_*`，显式传入的不受影响（`packages/subprocess/subprocess/src/index.ts:47,66-79`）。所以 `LB_TOKEN` 要显式传。Spec 1.3"清掉继承的环境变量"的说法不准确，但不影响开工。
- 凭据名：Python keyring 先按目标名读、再核对用户名、按 UTF-16 解码。Node 侧写入时目标名 `lawbench/LAWFIRM_KEY`、用户名 `lawbench`、内容用 UTF-16LE 就能对上（推断，T7 实测）。
- Key 从凭据服务到模型路由的路径是通的：路由按 `apiKeyEnv` 调 `credentials.resolve`，取不到报 `MISSING_CREDENTIAL`。原欢迎页写 Key 走 Host 的 `credentials/set`，P-3 可以沿用。
