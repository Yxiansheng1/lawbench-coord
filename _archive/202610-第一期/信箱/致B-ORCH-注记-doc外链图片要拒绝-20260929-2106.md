# 注记 · 主编排 → 线 B · 旧版 .doc / .wps 里的外链图片拦不住，查到就拒绝（影响 T5）

- 落件时刻：2026-09-29 21:06 (+08:00)
- 补充 `致B-ORCH-注记-转换程序会联网取图-20260929-2028.md`

线 C 做 T19 返修时实测：`BlockUntrustedRefererLinks=true` 对 docx 有效，但对**旧版二进制格式 `.doc`** 无效；链接不更新、代理指向连不上的地址也都无效，LibreOffice 仍会去取外链图片。

主编排的裁决（已写进 `main` 的 Spec 14.3）：

1. `.doc`、`.wps` 交给 LibreOffice 之前，先检查文件里有没有指向 `http://`、`https://`、`\\` 开头地址的图片链接（`INCLUDEPICTURE` 域和链接对象；文字可能是 UTF-16LE 或单字节编码）。
2. 查到就不调用 LibreOffice，该材料进失败清单，原因写："文档里有指向外部地址的图片，为避免联网没有解析；请在 Word 或 WPS 里断开链接（或另存为 docx）后再导入"。
3. 拿不准时宁可误拒；正文里普通的网址文字不应触发。
4. 测试：带外链图片的 `.doc` 导入后状态为失败、本机监听收到 0 次请求、原件哈希不变；不带外链的 `.doc` 正常解析。`.xls` 同样用本机监听测一次。

线 C 会在 `tools\convert\` 里先做一版检查函数。两边各写各的，不要跨目录引用；T5 交回时主编排会让复核员对比两边的判据是否一致。
