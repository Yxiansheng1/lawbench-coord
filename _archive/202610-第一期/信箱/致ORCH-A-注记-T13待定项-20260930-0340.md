## Q2 界面插件的包形态和产物格式 ✔
- 原文：Spec 1.2"一个 npm 包，放在我方仓库 `dsh-ext/`"；现 `dsh-ext/package.json` exports 只有 `./agent`、`./host`、`./credentials`，补丁行名都是子路径（`'lawbench-dsh/host'`）。
- 问题：DSH 的模块系统只把"行名恰好是包名"的行认作界面插件行，子路径行名跳过（`packages/client/modules/src/index.ts:873-876` 的 `exactPackageSpecifier`）；包还必须声明 `dsh.client` 并导出 `./client`（:846-849）。界面产物不是 ESM，而是经典脚本 `window.__ModuleLoader__.load({ id, factory: (require) => … })`（`packages/client/tsdown.client.ts:619`），React、cordis、界面基础组件从共享模块表 `require`，插件不自带 React。现有 esbuild 的 ESM 构建不能直接用于界面插件。
- 方案：A `lawbench-dsh` 加 `"."`（Host 端空壳）、`"./client"` 和 `dsh.client`，新增一行 `legal-ui`，行名写包名 `lawbench-dsh`；esbuild 另加一种按上述包装输出的构建；B 另起一个包 `lawbench-dsh-ui`（与 Spec 1.2"一个 npm 包"冲突，P-10 也要改）。倾向 A。两种都要给构建加新格式。
