# 注记 · 主编排 → 线 B · LibreOffice 的三件事（都影响 T5）

- 落件时刻：2026-09-29 22:18 (+08:00)
- 来源：T19 第二轮复核的实测。三条都已写进 `main` 的 Spec 5.2、14.3，`git rebase main` 之前以本件为准（你已交回的提交不要 rebase，在其后追加）

## 1. T5 那 6 个测试失败的原因，基本找到了

LibreOffice 会在配置目录下再建很深的子路径。**配置目录自身的路径长到约 146 个字符时 `soffice` 直接崩溃**，退出码 `0xC0000409`，没有任何输出；115 个字符时正常。T3 第二轮的两名复核员看到的正是这个退出码。

这不只是测试环境的问题：Spec 原来规定配置目录放在 `<案件>\工作区\临时\lo_profile`，而律师的案件文件夹路径常常很长。**真实使用时也会崩。**

Spec 5.2 已改，要求：

| 项 | 要求 |
|---|---|
| 配置目录位置 | `<应用数据>\临时\lo\<8 位随机>\`，每次转换新建、用完删除 |
| 删除 | 用长路径前缀（`\\?\`）并重试；失败要报出来、记日志，不能静默 |
| 启动时 | 清理 `<应用数据>\临时\lo\` 下的残留 |
| 被转换的副本和结果 | 仍在 `<案件>\工作区\临时\` |
| 调用前 | 检查配置目录路径长度，超过 100 个字符不调用，失败原因写"软件的数据目录路径太长" |
| `soffice` 以 `0xC0000409` 退出 | 失败原因写"转换程序异常退出"，不要写成"文件可能已损坏或加密" |
| 测试 | 在一个很长的案件路径下（案件根目录总长超过 150 个字符，含中文）导入 doc、xls、无缓存值的 xlsx，全部成功；全量测试在很深的 `--basetemp` 下通过 |

这条配置目录里会留"最近打开的文件"记录，所以"用完删除"和"启动清理"必须有测试守着（SEC-11）。

## 2. xlsx 交给 LibreOffice 重算时，会联网取外链图片

复核员实测：Calc 导入带外链图片的 xlsx 或 fods 时会发请求去取，`BlockUntrustedRefererLinks`、链接不更新这些设置都拦不住。

你的 T5 在"xlsx 有公式但没有缓存值"时会用 LibreOffice 重算。要求（Spec 14.3 ②b）：

1. 交给 LibreOffice 之前，先查压缩包里的关系文件（`xl/**/_rels/*.rels`）有没有 `TargetMode="External"` 的图片或对象关系。xlsx 是压缩包加 XML，这个检查是确定的，不是猜。
2. 有的话不交给 LibreOffice。该材料照常用 openpyxl 解析，没有缓存值的单元格只写公式，`note` 里写明"文档里有指向外部地址的图片，为避免联网没有重算公式"。
3. 测试：带外链图片、且有无缓存值公式的 xlsx 导入后，本机监听收到 0 次请求，没有起 `soffice`，`note` 有提示。
4. 外部工作簿引用、`WEBSERVICE` 这类公式：复核员实测 `.xls` 转换时不发请求。xlsx 重算时是否也不发，请你用本机监听测一次；发的话同样按上面处理。

## 3. `.doc` / `.wps` 的外链检查，判断范围要限定在域指令内

线 C 的第一版检查被绕过了（开关写在网址前面）。如果你的实现和它思路相同，请一并改：

- 只在域指令范围内匹配：域开始符 `0x13` 到分隔符 `0x14` 或结束符 `0x15` 之间。
- 链接类域名（`INCLUDEPICTURE`、`INCLUDETEXT`、`LINK`、`IMPORT`、`DDE`、`DDEAUTO`）之后、同一段域指令内**任意位置**出现 `http://`、`https://`、`ftp://`、`file://` 或 UNC 前缀就拒绝。
- UTF-16LE 和单字节两种解码都查；Data 流里单字节存放的地址前缀也查。
- 正文里普通的网址文字（包括英文的"see the link http://…"）不触发。
- 测试样本要有一份**只靠域代码这条检查**才能拦住的：用 LibreOffice 生成的 `.doc` 做底子，用 `olefile` 按原长度把域代码改成开关在前，并把 Data 流里的地址改掉。
