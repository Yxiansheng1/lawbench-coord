# T18 通用文书读取顺序恢复候选

## 结论

状态为 `SOURCE_ONLY_GENERAL_READ_ORDER_RECOVERY / AUTHORED_NOT_RUN`。根执行者尚未运行有限单元、正式 consumer、类型检查或构建，因此这份文件不能作为新功能通过证据。

本轮只处理通用文书的读取顺序观察：三问答完后的成功材料读取才进入既有材料循环；答案前的精确生产 read-gate 拒绝单独保留；未知错误、错配结果和答案后拒绝仍使报告失败。旧主流程报告保持原样。

## 改动

- 入口新增一个导出的纯分类器。输入为实际事件、三个声明问题 ID、实际提问/回答结果序号和当前 Agent 的 denial 函数。
- 启动时从入口当前导入的 compiled Agent 模块绑定一次 `questionsBeforeReadDenial`；没有复制中文拒答文本，也没有静态 fallback。
- 分类器要求提问与回答成功配对、三个答案 ID 精确且非空，材料/Wiki 成功读取严格晚于回答结果。
- 答案前只接受 `Error: ` 加当前 Agent denial 的逐字结果；拒绝尝试不进入返回值。答案后错误、未知来源、未知错误、缺结果、重复结果、`callId` 错配和答案前成功读取均判红。
- 既有材料循环只接收分类器返回的成功材料 `callId`。失败结果不会作为材料正文解析，也不会进入来源覆盖。
- 其余既有断言、材料事实、写入、单次合法提问、回调、预算、清理、JSONL 和报告逻辑保持原样。

有限单元 `general-read-order-finite.mts` 只使用内存事件包。它从入口抽取分类器及字面辅助函数，在隔离 VM 中运行，并从入口当前导入的 compiled Agent 模块取得真实 denial 导出。文件本身未运行，且不创建 NativeSession、任务、案件、模型、HTTP 或凭据路径。抽取器固定复用现有 TypeScript 编译器文件的字节数和哈希，没有给产品清单增加运行依赖。
